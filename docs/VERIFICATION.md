# Initial publication verification (2026-10-25)

Validation was performed locally on Linux/amd64. No production services were
restarted or production databases mounted during preparation of this repository.
Only public genesis-block data was read from a node to create a test fixture.

## Results

- ElectrumX, the optional dashboard, and the standalone legacy-image Brotli patch built.
- ElectrumX tests: **380 passed, 37 skipped, 23 subtests passed**. One inherited
  asyncio deprecation warning remains. Skips concern optional coin hashing/database
  implementations not installed in the test environment; they are not passed tests.
- Eight dedicated history-guard tests passed, including a temporary real LevelDB,
  invalid-state handling, threshold behavior, and compactor failure propagation.
- Pepecoin genesis parsing, header hash, previous hash, and transaction ID checks
  passed using the public mainnet genesis block, not fabricated blockchain data.
- Dashboard integration passed with synthetic RPC: missing password returns 503,
  spoofed localhost Host does not bypass that, incorrect/absent login is rejected,
  valid login/session persists, empty-node pages render, and source/data HTTP access
  returns 403. No PHP error markers were logged in that fixture.
- Split dashboard: PHP 8.2.35, Debian bookworm `libbrotli1 1.0.9-2+deb12u1`.
- Fresh daemon build: no Debian Brotli package, and aiohttp reports no Brotli decoder.
- Legacy compatibility build: Debian trixie `libbrotli1 1.1.0-2+deb13u1`. Image
  entrypoint, command, environment, user, workdir, declared ports and volumes match
  the original. File contents/modes match for its entrypoint, 320 dashboard entries,
  and 32 ElectrumX source files (excluding generated bytecode).
- Working tree and complete new Git history passed Gitleaks 8.30.1, with one narrow
  documented allowlist for an upstream public TokenPay address test vector. This is
  a scan result, not an absolute guarantee that no sensitive data could exist.

The first broad test run lacked optional altcoin test dependencies and a Pepecoin
block fixture. Installing those dependencies only in the test container and adding
the real public fixture resolved those failures; production dependencies were not
expanded to silence tests. Dashboard tests also caught legacy empty-node errors and
a duplicate session setting; those fixes have a separate non-security commit.

## Reproduce

```sh
docker build --pull -t pepecoin-electrumx-release:daemon electrumx
docker build --pull -t pepecoin-electrumx-release:dashboard dashboard
docker build --pull --no-cache -t pepecoin-electrumx-release:legacy-brotli patches/emgi-brotli

docker run --rm --entrypoint sh \
  -v "$PWD/electrumx/tests:/opt/electrumx/tests:ro" \
  -v "$PWD/tests:/release-tests:ro" -v "$PWD/scripts:/scripts:ro" -w /opt/electrumx \
  pepecoin-electrumx-release:daemon -c \
  'apt-get update && apt-get install -y --no-install-recommends build-essential && python -m ensurepip --upgrade && python -m pip install --no-cache-dir pytest pytest-asyncio blake256 groestlcoin-hash pycryptodomex && python -m pytest -q -p no:cacheprovider tests /release-tests'

python3 tests/check_dashboard.py --dashboard-image pepecoin-electrumx-release:dashboard \
  --python-image pepecoin-electrumx-release:daemon
python3 tests/check_legacy_patch.py --image pepecoin-electrumx-release:legacy-brotli
gitleaks git --redact .
gitleaks dir --redact .
```

The HTTP test creates its own randomly named bridge and containers, publishes only
an ephemeral loopback port, uses synthetic data and a deliberately public test-only
password fixture, then removes its own test resources. Never use that fixture as
a real deployment password. These checks need Docker access, which is privileged.

## Not established by these checks

- No full-chain reindex of the new source build or staged production-data migration
  has been completed. Operators must stage their own data and configuration.
- The third-party Discord bot source/configuration was not supplied. Its actual
  monitoring and control workflows still require validation.
- Other CPU architectures and every dependency's vulnerability status are not
  certified. These initial checks did not publish a registry image or signed
  release. See [container releases](CONTAINER-RELEASES.md) for the candidate pipeline
  and [release security](RELEASE-SECURITY.md) for the subsequent package scans.
- PHP dashboard defaults intentionally differ from the old combined image. Use the
  standalone compatibility patch if retaining those interfaces is your immediate requirement.
