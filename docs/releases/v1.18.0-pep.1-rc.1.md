### Full-chain test progress

The published image's isolated fresh index was cleanly paused and flushed at
height 294,772 after two recoverable transport errors in the operator's read-only
Core bridge. The bridge was adjusted to use smaller batches, transport retries,
and SSH compression. The same image and test database then reopened successfully
and indexing continued. A later router outage interrupted the SSH bridge; a clean
shutdown retained height 868,723. The same database then reached the chain tip.
Original logs and all resumed-run metadata are retained; this was not an
uninterrupted index.

Final verification passed before restart at height 1,266,063 and after restart
against height 1,266,064, with live header responses advancing to 1,266,066. It
checked Core/header hash agreement, transaction hashes and Merkle proofs, the
packaged administrative CLI, TCP, certificate-verified TLS/WSS, and persistence.
The final run contained no ElectrumX error markers and exited successfully.

Qualification: an earlier immediate probe timed out while the startup header
Merkle cache was still being prepared. The diagnostic rerun waited for the
cache-complete log marker (about 65 seconds on the two-CPU test container) before
running the original strict RPC/protocol assertions. No runtime image was changed
and no assertion was suppressed. An open port alone is not a readiness signal;
the reusable harness still needs that explicit startup-readiness wait for a full
database. Production services were not restarted or changed.

## What is not established

- The third-party Discord bot was not supplied. Its actual integration is unverified.
- Other CPU architectures are untested. No multi-platform release is claimed.
- This candidate is the daemon only. A separately patched, optional
  [dashboard candidate](dashboard-v1.0.0-rc.1.md) is now available; wallets and
  direct Electrum RPC clients do not require it.

## Opt-in use

Follow [migration](../MIGRATION.md) and [container setup](../CONTAINER-RELEASES.md).
Use a separate test database and your own configuration/certificates first. Do not
replace the original combined image blindly or run two writers on the same volume.
Set `ELECTRUM_IMAGE` to the full registry-digest reference above in your private
`.env`; then pull and start with `docker compose up -d --no-build electrumx`.

There is no `latest` tag or automatic stable promotion. Keep an untouched matching
database backup and previous image for rollback.
